Write it down once

29 July 2026

Your agent can reach your calendar now. So you ask it to find an hour for the team sync this week.

It books 4:30 on Friday.

Nothing failed. The hour really was free; nobody had claimed it. It’s just that nobody on your team takes a meeting after four on a Friday, and Tuesday morning is kept clear for focus work — which is not written down anywhere, it’s simply understood, the way most things at a company are understood.

So you tell it. Not Friday afternoons, not Tuesday mornings, and forty-five minutes rather than an hour, because the hour always overruns. It apologises, rebooks, gets it right.

Then you open a fresh conversation next week and it books 4:30 on a Friday.

Why you keep saying it twice

Every conversation starts empty. Whatever you explained last time went out with the conversation it was in, so the agent comes back knowing how to reach the calendar and nothing at all about how you use it.

There’s a standard fix, and it’s a good one: a file — CLAUDE.md is the usual name — that sits alongside your work and gets read at the start of every session. Put the meeting rules in there and they’re waiting before you’ve typed a word. No more repeating yourself.

That’s the right first move, and for a good while it’s enough. The file never stops being read — it just keeps getting longer.

The meeting rules earn their place, so the invoice rules go in too. Then how we name files. Then which spreadsheet the numbers come from, and the two exceptions to that, and the thing about the Berlin office. Every addition is sensible on its own, and somewhere along the way the file stops being a short note about your project and becomes a manual.

Every word of that manual is read at the start of every session. Including the ones where you just wanted a typo fixed.

And it isn’t a one-off charge. Everything the model can see at once — that file, plus everything said in the conversation so far — is called its context, and it holds only so many words. All of it is read again on every turn of the conversation. So the invoice rules aren’t paid for once. They’re paid for again on every exchange, in every session, for as long as they stay in the file.

So what is a skill?

A skill is one job’s worth of instructions that the agent only picks up when that job comes up. What it’s made of is far less impressive: a folder, with a markdown file in it. Nothing else is required.

The file is called SKILL.md. It opens with two labelled lines, fenced off above and below by three dashes: a short name for the skill, and a sentence saying what it’s for and when to use it. Underneath goes the procedure, in plain English — the same words you’d use explaining it to a new colleague.

booking-meetings / SKILL.md
---
name: booking-meetings
description: How this team books meetings — use it whenever you’re putting something in someone’s calendar.
---

Never book after 16:00 on a Friday.
Tuesday 09:00–12:00 is kept clear for focus work.
Default to 45 minutes rather than an hour.
More than five people means a week’s notice.
If the only free slot breaks one of these, ask instead of booking.

Those dashes are the only piece of syntax in the file, and they matter: they’re how the assistant finds the name and the description without opening the rest. Leave them out and it reads the file with no description at all, so nothing ever matches it and the skill quietly never fires.

Everything under them is plain writing, in any text editor, and if you can write a decent set of instructions for a person, you can write one. There’s a bit of setup to get your assistant reading it — one toggle, or one folder — and that comes later.

The part that’s different: when it arrives

The interesting thing about a skill isn’t what’s in the file. It’s when the agent reads it.

Say you’ve written five of these — meetings, invoices, file names, house style, handover notes. The agent holds five sentences, not five procedures: the one at the top of each file, the one that says what this is for. That’s all that sits there while you work.

Ask it to book the team sync, and the agent reads those five sentences and picks the one that fits. Only then does it open that file and read the rest. The other four stay on the shelf.

The four that didn’t match stayed on the shelf. Their sentences are in the context. Their contents aren’t.

A hundred pages on the shelf costs you one sentence.

Context usually works one way. Once something enters it, it stays, and you keep paying for it: tool descriptions, standing instructions, all of it read again on every turn.

A skill breaks that. The procedure isn’t cheaper — it just isn’t loaded until it’s relevant. Most of the time it never needs to be.

None of this makes the agent more capable, though. Writing down how your team books meetings doesn’t let it touch a calendar; it still needs the calendar connection for that, exactly as before.

The typo request is the one to try in both modes. With skills it matches none of the five sentences, so it opens nothing — from a fresh conversation, the context doesn’t move at all. With everything in the standing-instructions file, all five procedures are there regardless, because that file doesn’t know what you were going to ask.

The procedures here are five lines each, which flatters the standing-instructions file — the descriptions look expensive next to them. Real procedures run to pages. The longer they get, the wider that gap opens.

Write it down once, and it turns up when it’s needed.

Skills travel

A CLAUDE.md belongs to one assistant, by name. A skill doesn’t. The format is published as an open standard, so the same folder works in any assistant that supports it without being rewritten — on your machine or a colleague’s. That’s the other reason not to keep a procedure in a file named after a product.

Three things worth knowing before you rely on this

Loading isn’t unloading

Once a skill opens, it stays open. In Claude Code, the documentation is specific about it: the file’s contents enter the conversation as a message and stay there for the rest of the session, and the file isn’t re-read on later turns. Loading it is a one-way trip. From that point on, it’s part of the conversation like everything else.

Invoke six skills in one conversation and you’re carrying six procedures, not one. If a skill seems to stop having any effect later, the text is often still there and the model has just moved on — though in a very long conversation it may also have been pushed out. Starting a fresh conversation resets either way.

It only helps if it gets picked

That one-sentence description at the top is what gets a skill chosen. If it’s vague, the agent may never open the skill, no matter how good the rest of it is.

There’s another limit, too. In Claude Code, the list of descriptions is given a budget — 1% of the context window by default, raisable in settings — and each description has a ceiling of its own on top of that. Once you have enough skills, descriptions begin to be shortened or dropped, starting with the ones you use least. A perfectly good skill can stop being found, and nothing tells you.

Still in Claude Code, typing /context shows how much of the context window that list is currently using. It counts in tokens rather than words — tokens being the smaller pieces a model actually reads. This post says “words” because they’re easier to picture.

Installing a skill is installing software

A skill can contain scripts as well as instructions, and those scripts run with whatever permissions the agent has. Anthropic’s advice is simple: install skills from sources you trust, and read what’s in the folder before using them.

That matters because the format is open. In February 2026, a security firm audited ClawHub, a marketplace where users of OpenClaw go to find ready-made skills — OpenClaw being a separate open-source agent, not an Anthropic product, that happens to use the same format. Of the 2,857 skills examined, 341 were malicious, and 335 of those carried the same stealer. What it took went well past saved passwords, as far as crypto wallet keys and the credentials people use to log into their own servers. The firm sells agent security software and launched a scanner in the same post, so weigh its claims accordingly; it published its method, and the findings were picked up and reported elsewhere.

What to actually do

Write one. Not five.

Think of the thing you explained twice this week — the same correction, the same preference, the same “no, we always do it the other way”. That’s your first skill. Put it in a file, use it for a fortnight, and only then write another. Five skills written in one afternoon are five guesses about what you’ll need; one skill written after the second time you got annoyed is a real one.

If you’ve never opened a terminal, this lives in Claude under Customize → Skills. You’ll need code execution switched on under Settings → Capabilities first — that toggle is named for what it permits, not for what your skill has to contain, so one made only of instructions still needs it. On Team and Enterprise plans it’s switched on under organisation settings instead, and the help pages walk through both routes. If you’re working in a project folder already, it’s a .claude/skills folder with one subfolder per skill, each holding its SKILL.md.

Then check what it costs you. In the terminal that’s /context, run before you add the skill and again afterwards — the number should barely move, and if it moves a lot, your description is doing too much talking. Outside the terminal you don’t get that figure, so the check is cruder: if the description at the top has grown past a sentence, cut it back.

The next wall

So the procedure is written down, and it’s being followed. Meetings get booked properly now.

Then you ask for something bigger. Research three options, recommend one, write the email that explains the choice.

It does all of it, in order, and the email is fine.

The trouble started before the email.

That all happened in one conversation. By the time it’s writing the email, it’s still carrying all the comparisons, the options it threw out, the notes from research it finished twenty minutes ago. That research is done, but it never left the room.

Skills kept every procedure from sitting in the conversation at once. They do nothing about work that’s already in there.

That’s what sub-agents solve, and they’re next.
