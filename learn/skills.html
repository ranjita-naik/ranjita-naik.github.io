Write it down once

29 July 2026

Your agent can reach your calendar now. So you ask it to find an hour for the team sync this week.

It books 4:30 on Friday.

Nothing failed. It read the calendar, found an hour nobody had claimed, and put the meeting in it. The hour really was free. It’s just that nobody on your team takes a meeting after four on a Friday, and Tuesday morning is kept clear for focus work — which is not written down anywhere, it’s simply understood, the way most things at a company are understood.

So you tell it. Not Friday afternoons. Not Tuesday mornings. Forty-five minutes rather than an hour, because the hour always overruns. It apologises, rebooks, gets it right.

Then you open a fresh conversation next week and it books 4:30 on a Friday.

Why you keep saying it twice

Every conversation starts empty. Whatever you explained last time went out with the conversation it was in, so the agent comes back knowing how to reach the calendar and nothing at all about how you use it.

There’s a standard fix, and it’s a good one: a file — CLAUDE.md is the usual name — that sits alongside your work and gets read at the start of every session. Put the meeting rules in there and they’re waiting before you’ve typed a word. No more repeating yourself.

That’s the right first move, and for a good while it’s enough. What eventually goes wrong isn’t that the file stops being read. It’s that it grows.

The meeting rules earn their place, so the invoice rules go in too. Then how we name files. Then which spreadsheet the numbers come from, and the two exceptions to that, and the thing about the Berlin office. Every addition is sensible on its own, and somewhere along the way the file stops being a short note about your project and becomes a manual.

Every word of that manual is read at the start of every session. Including the ones where you just wanted a typo fixed.

And it isn’t a one-off charge. Everything sitting in the agent’s context is re-read on each turn of the conversation — so the invoice rules aren’t paid for once, they’re paid for again on every exchange, in every session, for as long as they stay in the file.

So what is a skill?

A skill is one job’s worth of instructions that the agent only picks up when that job comes up. What it’s made of is far less impressive: a folder, with a markdown file in it. That’s the whole thing.

The file is called SKILL.md. At the top of it goes a sentence saying what this is for and when to use it. Underneath goes the procedure, in plain English — the same words you’d use explaining it to a new colleague.

booking-meetings / SKILL.md

The sentence at the top

How this team books meetings. Use it whenever you’re putting something in someone’s calendar.

The procedure

  • Never book after 16:00 on a Friday.
  • Tuesday 09:00–12:00 is kept clear for focus work.
  • Default to 45 minutes rather than an hour.
  • More than five people means a week’s notice.
  • If the only free slot breaks one of these, ask instead of booking.

There’s no code in that, and none is required. Nothing to install, nothing to sign up for. It’s a file you could write in any text editor, and if you can write a decent set of instructions for a person, you can write one.

The part that’s different: when it arrives

The interesting thing about a skill isn’t what’s in the file. It’s when the agent reads it.

Say you’ve written five of these — meetings, invoices, file names, house style, handover notes. The agent isn’t holding those five procedures. It’s holding five sentences: the one at the top of each file, the one that says what this is for. That’s all that sits there while you work.

Ask it to book the team sync, and the sentence about meetings matches what you’ve asked. Only then does it open that file and read the rest. The other four stay shut.

The four folders that didn’t match were never opened. Their sentences are in the context; their contents aren’t.

You can hand it a hundred pages and pay for one sentence.

That’s worth sitting with, because context has only ever worked one way: once something enters it, it stays, and you keep paying for it. Tool descriptions. Standing instructions. Every turn of the conversation reads them again.

Skills change that. The procedure isn’t cheaper — it just isn’t loaded until it’s relevant. Most of the time it never needs to be.

That doesn’t make the agent more capable, though. Writing down how your team books meetings doesn’t let it touch a calendar; it still needs the calendar connection for that, exactly as before. Skills change what the agent knows about doing the job, not what it can reach.

With everything in the standing-instructions file, all five are there anyway, because that file doesn’t know what you were going to ask.

Write it down once, and it turns up when it’s needed.

It isn’t Claude’s

A CLAUDE.md belongs to one assistant, by name. A skill doesn’t. The format is published as an open standard, so the same folder works in other assistants that support it, and on a colleague’s machine, without being rewritten — which is the other answer to why a procedure shouldn’t live in a file named after a product. Hold on to that. It comes back in a minute, wearing different clothes.

Three things worth knowing before you rely on this

Loading isn’t unloading

Once a skill opens, it stays open. In Claude Code, the documentation is specific about it: the file’s contents enter the conversation as a message and stay there for the rest of the session, and the file isn’t re-read on later turns. So “free until you need it” is exactly true, and “free afterwards” is not — from the moment it matched, you’re carrying it. Invoke six skills in one long session and you’re carrying all six. There’s a related trap in the other direction: if a skill seems to stop having any effect after the first reply, the text is usually still sitting there and the model has simply moved on to other approaches. Starting a fresh conversation is the blunt fix for both.

It only helps if it gets picked

That sentence at the top is what gets the skill chosen, which means a vague one quietly costs you the whole file. And the list of those sentences has a ceiling of its own. In Claude Code the listing is held to about 1% of the context window; past that, descriptions get shortened or dropped, starting with the skills you invoke least. The practical version: your twentieth skill can stop being findable without anything appearing to go wrong. Still in Claude Code, typing /context shows what that listing currently costs.

Installing a skill is installing software

A folder can carry scripts as well as words, and those run with whatever permissions the agent has. Anthropic’s own guidance is to install from sources you trust and read what’s in the folder first — and that’s the same advice you’d give about anything else you download, which is rather the point. Remember the open standard from a minute ago: portability runs both ways. In February 2026 a security firm audited the skill marketplace belonging to OpenClaw — a separate open-source agent, not an Anthropic product, that happens to use the same file format — and found 341 malicious skills among the 2,857 it checked, most of them from a single campaign that was stealing saved passwords. The firm sells security tooling for agents and launched a product in the same post, so weigh it accordingly; the audit is public, it was picked up independently, and you can read both and decide.

What to actually do

Write one. Not five.

Think of the thing you explained twice this week — the same correction, the same preference, the same “no, we always do it the other way”. That’s your first skill. Put it in a file, use it for a fortnight, and only then write another. Five skills written in one afternoon are five guesses about what you’ll need; one skill written after the second time you got annoyed is a real one.

If you’ve never opened a terminal, this lives in the Claude app under Customize → Skills — you’ll need code execution switched on under Settings → Capabilities first, and the help pages walk through both. If you’re working in a project folder already, it’s a skills folder with one subfolder per skill, each holding its SKILL.md.

Then check what it costs you. In the terminal that’s /context, run before you add the skill and again afterwards — the number should barely move, and if it moves a lot, your description is doing too much talking. The app doesn’t give you that figure, so there the check is simpler: keep the sentence at the top to one sentence.

The next wall

So the procedure is written down, and it’s being followed. Meetings get booked properly now.

Then you ask for something bigger. Look into three options, write up a recommendation, then check it against what we agreed last quarter. And it does all three — in one conversation, in one go, dragging every scrap of half-read research into the writing, then reviewing its own work with the whole messy business still sitting in front of it.

It isn’t bad at researching, or writing, or checking. It’s that one worker is doing three jobs in one room, and never gets to put the first one down.

The fix has a name — sub-agents — and it’s the next thing in this part of the series.
